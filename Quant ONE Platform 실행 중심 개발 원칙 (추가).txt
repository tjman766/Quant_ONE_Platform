Quant ONE Platform 실행 중심 개발 원칙 (추가)

앞으로는 아래 원칙을 항상 적용합니다.

Repository Audit
✅ 확인한 내용만 Audit에 기록
❌ 확인하지 않은 내용은 추측하거나 작성하지 않음
✅ Audit은 실제 GitHub 저장소 또는 실제 업로드된 ZIP을 기준으로 수행
Sprint 산출물
✅ 실제 저장소 상태를 기준으로 작성
❌ 예시나 가상의 구조를 실제 결과처럼 작성하지 않음
Change Plan
✅ 반드시 Repository Audit과 Impact Analysis를 근거로 작성
❌ Audit 없이 변경 계획을 만들지 않음
개발 방식
Repository Audit → 영향 분석 → 구현 계획 → 구현 → 테스트 → 문서 → Release

이 순서를 기본 프로세스로 유지합니다.
